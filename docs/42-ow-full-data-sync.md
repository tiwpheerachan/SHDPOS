# ดึงข้อมูล OW UAT ทุกประเภท — 22 พฤศจิกายน 2026

## ผลรอบจริง

- สินค้า 33 SKU: อ่าน list ทุกหน้าและ exact detail ครบ อ้างสินค้า POS เดิมได้ 33 ไม่มี SKU ใหม่หรือขัดแย้งในรอบนี้
- คลัง 2 แห่ง: 33856 และ 33857
- สต๊อก 66 รายการ = 33 SKU × 2 คลัง (รวมรายการที่ยอดเป็น 0)
- ขนส่ง 8 รายการ
- รายการใบโอนทุกสถานะ: 0 ใบทั้งสองคลัง จึงไม่มี ID ให้ดึงรายละเอียด/ประวัติใบโอนต่อ
- Dashboard 2 คลัง: เก็บข้อมูลต้นทางไว้ แม้ตัวนับกิจกรรมเป็น 0
- เก็บ OpenAPI และผลอ่านสต๊อกแบบไม่ระบุ SKU ด้วย ซึ่งรอบนี้คืนรายการว่าง ต่างจากการอ่านสต๊อกแบบระบุ SKU ที่ได้ข้อมูลครบ
- BOM ตอบ HTTP 501: บันทึกว่า API ยังไม่รองรับ ไม่แปลว่าเป็นสินค้าชุดที่ไม่มีส่วนประกอบ
- SN: ไม่มีเลขอ้างอิงในใบโอน/ประวัติให้ค้นหา และไม่มี endpoint enumerate SN ทั้งหมด จึงไม่เดาเลขหรือสร้างข้อมูลทดแทน
- อ่านข้อมูลสำเร็จโดยไม่มี error; มี 2 หมวดที่ยังดึงต่อไม่ได้ตามข้อจำกัดข้างต้น

## เปิดดูในระบบ

เข้า `/admin/onewarehouse` → กล่อง “ข้อมูลต้นทางที่เก็บใน POS”

1. เห็นจำนวนข้อมูลและเวลาที่ดึงล่าสุด
2. เลือกหมวด สินค้า / คลัง / สต๊อก / ขนส่ง / ใบโอน / Dashboard / SN / BOM
3. กดแถวเพื่อเปิด Drawer ดูตารางและ JSON ต้นทางทั้งหมด
4. กด “ดึงข้อมูลทั้งหมด” เมื่อต้องการอ่านรอบใหม่
5. ใช้ลิงก์ “ตรวจนำเข้าสินค้า / ผูกคลัง” เพื่อเปิดกระบวนการจับคู่สินค้าและคลังเดิม

การอ่าน/สั่งซิงก์ใช้ guard เดียวกับการจัดการแคตตาล็อก คือผู้ใช้ active มีสิทธิ์จัดการสินค้าและต้นทุนระดับบริษัท

## การจัดเก็บ

ข้อมูลอยู่ใน private Supabase Storage bucket `pos-ow-snapshots` แยก namespace ตาม source/environment มี archive ตาม run ID และ `latest.json` ให้ API ของ POS อ่าน ไม่เปิด bucket เป็น public และไม่สร้าง public URL

มีสำเนา JSON ส่งให้ผู้ใช้ใน outputs ของงานนี้ด้วย ไม่เก็บ service token หรือ header ยืนยันตัวตนในข้อมูล

## ขอบเขต

การดึงรอบนี้เก็บข้อมูลสำหรับตรวจเทียบ ไม่ลงยอด Stock ขาย ไม่รับใบโอนแทนพนักงาน ไม่เปิดใช้สินค้า ไม่เดาว่าคลัง OW เป็นสาขา POS ใด และไม่ส่ง POST/PATCH ไป OW

ตัวอ่านพร้อมเดิน pagination ใบโอน และจะดึงรายละเอียด ประวัติ และสถานะ SN ตามเลขที่พบจริงเมื่อมีเอกสาร รองรับการตรวจ cursor/หน้าซ้ำและแยกอ่านล้มเหลวออกจากรายการว่าง จำนวนสินค้ามาจากแคตตาล็อกที่ API เปิดให้บัญชีบริการอ่านได้

เมื่อแคตตาล็อกต้นทางมี SKU ใหม่ จะแสดงผลจับคู่ว่ายังไม่นำเข้า ต้องผ่านตัวนำเข้าแคตตาล็อกเดิมเพื่อรักษา ID และตรวจข้อมูลก่อนขาย

## ตรวจสอบแล้ว

- อ่าน snapshot กลับจาก private storage และเทียบตรงกับไฟล์สำเนา
- ทดสอบ pagination สินค้าและใบโอน, coverage สต๊อก, 0 เทียบกับอ่านไม่ได้, ID สินค้า, SN อ้างอิงจริง, หน้าซ้ำ, partial failure, authorization และห้ามใช้ bucket public
- TypeScript และชุดทดสอบผู้ใช้จริงผ่าน

ข้อจำกัดการตรวจหน้าจอในรอบนี้: session เบราว์เซอร์ต้องเข้าสู่ระบบใหม่ และ SSO ตอบว่า redirect_uri ของ localhost:3100 ไม่ตรงที่ลงทะเบียน จึงยังไม่ได้ยืนยันหน้าสรุปด้วยบัญชีจริงผ่านเบราว์เซอร์ ข้อมูลฝั่งเซิร์ฟเวอร์ดึงและอ่านกลับสำเร็จแล้ว
