## 1. POS Checkout

**เป้าหมาย: จากหยิบสินค้าถึงออกใบเสร็จ ไม่เกิน 4–5 การกด**

```
สแกนสินค้า → ตะกร้า → เลือกพนักงานขาย → ชำระเงิน → ใบเสร็จ
```

### หน้าจอ
- ซ้าย: ช่องสแกน/ค้นหา + แถบหมวด + กริดสินค้า (แสดงสต๊อกคงเหลือบนการ์ด)
- ขวา: พนักงานขาย, ลูกค้า, รายการในตะกร้า, ยอดรวม, ปุ่มชำระเงินเต็มความกว้าง

### การสแกน
ช่องค้นหาโฟกัสตลอดเวลา เครื่องสแกนบาร์โค้ดทำงานเหมือนคีย์บอร์ด + Enter
ลำดับการค้นหา: barcode ตรงตัว → SKU ตรงตัว → ถ้าผลลัพธ์เหลือ 1 รายการให้เพิ่มเลย

### คีย์ลัด
`F2` ชำระเงิน · `F4` พักบิล · `/` ไปช่องค้นหา

### ส่วนลด
- รายบรรทัด และท้ายบิล, ใส่เป็น % หรือ ฿ ก็ได้
- เกินเพดาน role → เปิด ApprovalModal (ดู `03-permissions.md`)

### Serial / IMEI
สินค้า `track_serial = true` ต้องสแกนให้ครบจำนวนก่อนจ่ายเงิน
ถ้ายังไม่ครบแล้วกดชำระเงิน ระบบเด้งกลับมาที่ช่องสแกน serial พร้อมแจ้งเตือน

### ช่องทางชำระเงิน
`cash · credit_card · debit_card · qr_promptpay · bank_transfer · edc · gift_card · store_credit · installment · online_marketplace`

**Mixed payment**: เพิ่มได้หลายแถวในบิลเดียว
```
ยอดสุทธิ ฿15,000
  เงินสด        ฿5,000
  บัตรเครดิต    ฿10,000
```
ปุ่มลัดเงินสดคำนวณธนบัตรถัดไปให้อัตโนมัติ (ยอดพอดี / ปัดร้อย / ปัดพัน)

### พักบิล (Hold)
เก็บตะกร้าไว้ใน IndexedDB แล้วเรียกคืนได้ — ใช้ตอนลูกค้าเดินไปหยิบของเพิ่ม

## 2. Orders & Receipt

- รายการบิลวันนี้ / 7 วัน + ค้นหาตามเลขที่บิลหรือชื่อลูกค้า

## 3. Return / Exchange

```
ค้นหาบิลเดิม → เลือกรายการ + จำนวน → ระบุสภาพสินค้า
→ เลือกประเภท (คืนเงิน / เปลี่ยนสินค้า / เคลมประกัน)
→ เหตุผล → ช่องทางคืนเงิน → อนุมัติ (ถ้าจำเป็น) → บันทึก
```

| สภาพสินค้า | คืนเข้าสต๊อก? |
|---|---|
| ขายต่อได้ (sellable) | ✅ |
| กล่องเปิดแล้ว (opened_box) | ❌ (แยกไว้ขายลดราคา) |
| ชำรุด (defective) | ❌ (เข้ากอง claim) |
| ตัดทิ้ง (scrap) | ❌ |

เหตุผลมาตรฐาน: สินค้าชำรุด · ได้ของผิดรุ่น · ลูกค้าเปลี่ยนใจ · เคลมประกัน · คิดราคาผิด

**Staff ต้องขออนุมัติทุกครั้ง** · Supervisor ขึ้นไปทำได้เอง
การคืนเงินสร้าง `tax_documents` ชนิด `credit_note` (ใบลดหนี้) — ดู `07-etax-invoice.md`

## 4. Inventory

- สต๊อกรายสาขา + จุดสั่งซื้อรายสินค้า/รายสาขา
- Ledger `stock_movements` ตอบได้เสมอว่าของหายไปไหน
- **แจ้งเตือนอัตโนมัติ**: `check_low_stock()` ถูกเรียกทุกครั้งที่สต๊อกเคลื่อนไหว
  สร้าง `notifications` (severity `warn` เมื่อ ≤ จุดสั่งซื้อ, `critical` เมื่อ = 0)
  และปิดใบแจ้งเตือนเองเมื่อเติมของแล้ว
- หน้า Admin เห็นมูลค่าสต๊อกตามต้นทุน (เฉพาะคนที่มีสิทธิ์ `report.cost`)

## 5. Transfer & Stock Count

### Transfer — 10 สถานะ

```
draft → pending_approval → approved → picking → packed
      → shipped → in_transit → received → completed
                                   ↘ partial_received → completed
      ↘ cancelled / rejected
```

- ตัดสต๊อกต้นทางตอน `shipped` · เพิ่มปลายทางตอน `completed`
  (ของที่อยู่ระหว่างทางไม่ถูกนับทั้งสองฝั่ง)
- ปลายทางสแกนรับทีละชิ้น เทียบ `qty_requested` กับ `qty_received`

```
คาดว่าจะได้รับ 5
รับจริง        4
ขาด           1     ← เข้า discrepancy workflow อัตโนมัติ
```

### Stock Count (Cycle Count)

```
นับสต๊อก
สาขา  Anker Central Rama 9
โซน   Display Area

Anker 737     ควรมี 12    นับได้ [ 11 ]    ส่วนต่าง -1
```

ส่งผลการนับ → สร้าง `count_adjust` movements + audit log `stock_count`
นับเป็นโซนได้ ไม่ต้องปิดร้านนับทั้งร้าน

## 6. Employee / Shift / Cash Register

### เปิดกะ
เลือกเงินสดตั้งต้น + **ติ๊กพนักงานที่เข้ากะพร้อมกัน** (แก้โจทย์สาขาที่มี 2 คนต่อกะ)

### ระหว่างกะ
- เปิดลิ้นชักโดยไม่ขาย (`open_no_sale`) — ต้องมีสิทธิ์ + บันทึก audit
- เติม/ถอนเงินสด (`cash_in` / `cash_out` / `drop` / `pickup`)

### ปิดกะ
```
เงินสดตั้งต้น       2,000.00
ขายเงินสด          8,450.00
เงินสดที่ควรมี     10,450.00
เงินสดที่นับได้    [10,430.00]
ส่วนต่าง             -20.00      ← เขียนลง audit log เสมอ
```

ผู้จัดการปิดกะแทนได้ (`shift.force_close`) กรณีพนักงานลืมปิด

## 7. Customer / Member

- ค้นหาด้วยเบอร์โทร / ชื่อ / รหัสสมาชิก
- เก็บข้อมูลออกใบกำกับภาษีเต็มรูป (เลขผู้เสียภาษี, ชื่อ, ที่อยู่, สาขา, อีเมล)

## 9. Analytics & Performance

### Dashboard
- KPI: ยอดขายรวม · จำนวนบิล · ยอดเฉลี่ยต่อบิล · กำไรขั้นต้น + %เทียบช่วงก่อนหน้า
- กราฟยอดขายรายวัน + เส้นประเปรียบเทียบช่วงก่อนหน้า
- แยกตามสาขา (bar) · แยกตามแบรนด์ (donut) · สัดส่วนช่องทางชำระ (donut)
- ยอดขายรายชั่วโมง → ใช้วางแผนกะ
- Top พนักงาน / Top สินค้า
- แจ้งเตือนสต๊อกใกล้หมด
- Live feed บิลล่าสุด

### ตัวกรอง
ช่วงเวลา (วันนี้ / 7 / 30 / 90 วัน) × หลายสาขา × หลายแบรนด์
ทุกตัวกรองถูกจำกัดด้วย data scope ของผู้ใช้อัตโนมัติ

### Performance รายคน
ยอดขาย · จำนวนบิล · จำนวนชิ้น · ยอดเฉลี่ยต่อบิล · กำไรขั้นต้น
คิดจาก `order_items.salesperson_id` → แม่นแม้ 2 คนเข้ากะพร้อมกัน

### Export
CSV (UTF-8 BOM เปิดใน Excel ภาษาไทยไม่เพี้ยน) ทั้งหน้ายอดขาย สต๊อก และ audit log
