# งานของฉัน การส่งต่องาน และปฏิทินขาย

อัปเดต 23 พฤศจิกายน 2026 — migrations 0046–0047

## เปิดใช้งาน

- หน้าร้าน: `/pos/work` เมนู “งานของฉัน” บนแถบเมนู
- หลังบ้าน: `/admin/work` เมนู “งานของฉัน” ใต้ภาพรวม
- บิลรอปิดหลังบ้าน: `/admin/deferred-sales` รองรับลิงก์เปิดบิลตรงจากงาน
- เมนู “ติดตามลูกค้า” เดิมยังเป็นงาน CRM ของลูกค้า ไม่ถูกแทนที่

ทั้งสองหน้าทำงานกับฐานข้อมูลชุดเดียวกัน ไม่ใช่รายการจำลองหรือสำเนาแยกต่อเครื่อง

## รูปแบบหน้าจอ

ใช้การ์ดโทนขาวโปร่ง เงาบาง มุมโค้ง และการ์ดเน้นสีเข้มตามธีมเดิม ปุ่มเครื่องมือสูง 32px ข้อความสั้น แยกข้อมูลหลักกับคำอธิบาย

Modal และ Drawer ย้ายไป render ที่ body ผ่าน portal เพื่อไม่ถูก parent ตัดขอบ มีเพดานความสูงตาม visual viewport เลื่อนเนื้อหาภายใน แถบปุ่มอยู่ในกรอบ มี focus trap และคืน focus เมื่อปิด รองรับพื้นที่ที่เหลือเมื่อแป้นพิมพ์มือถือเปิด

หน้ารอปิดบิลใช้แผงรายละเอียดที่แคบลง แบ่งข้อมูลเป็นกลุ่ม ปุ่มท้ายแผงเป็น “บันทึกข้อมูล” และ “ตรวจและปิดบิล” ไม่ใช้ปุ่มใหญ่เต็มความกว้างทุกคำสั่ง

## มุมมองงาน

1. **ภาพรวม** — งานเปิด งานเกินกำหนด งานเสร็จ หมุดส่วนตัว รายการสำคัญ และงานลำดับถัดไป
2. **รายการงาน** — ค้นหาชื่องาน/ผู้รับผิดชอบ กรองสถานะ และเปิดรายละเอียด
3. **ปฏิทินงาน** — เปลี่ยนเดือน คลิกวันที่ดูงาน เวลาที่แสดงใช้กรุงเทพฯ งานไม่มีกำหนดแสดงตามวันสร้าง
4. **ปฏิทินขาย** — ยอดรายวัน จำนวนบิล และยอดเงินรอลงบิลแยกกัน กดวันที่ดูยอดตามชั่วโมงและ SKU/จำนวน/มูลค่ารายการ

ตัวกรองงาน:

- **ของฉัน**: ผู้รับผิดชอบปัจจุบันคือเรา
- **ส่งต่อโดยฉัน**: งานที่เราสร้างและมอบหมายให้คนอื่น
- **ทีมที่ดูแล**: เฉพาะหัวหน้า ภายในสาขา/แบรนด์ที่ได้รับสิทธิ์

## สร้างและส่งต่อ

1. กด “สร้างงาน” ระบุชื่อ รายละเอียด สาขา ผู้รับผิดชอบ ความสำคัญ และกำหนดส่ง
2. เลือกได้เฉพาะผู้ใช้ที่ active มีสิทธิ์แอป และมีสิทธิ์สาขาของงาน รวมถึงหัวหน้าที่ดูแลสาขาหรือบริษัท
3. เปิดรายละเอียดเพื่อเปลี่ยนสถานะ ผู้รับผิดชอบ กำหนดส่ง หรือเขียนข้อความอัปเดต
4. หากเปลี่ยนผู้รับผิดชอบ ต้องมีเหตุผลส่งต่ออย่างน้อย 3 ตัวอักษร
5. งานและประวัติบันทึกใน transaction เดียว พร้อมแจ้งเตือนผู้รับใหม่ ผู้รับเดิม และผู้สร้าง โดยไม่ส่ง event ซ้ำสำหรับ version เดียว
6. ถ้าอีกเครื่องแก้งานไปแล้ว ระบบปฏิเสธ version เก่า ให้โหลดล่าสุดก่อนแก้ต่อ

สถานะ: รอทำ → กำลังทำ / ติดขัด → เสร็จแล้ว หรือยกเลิก งานทั่วไปเปิดกลับได้ แต่สถานะงานที่ผูกบิลต้องสอดคล้องกับบิลจริง

## ปักหมุด

หมุดเป็นของแต่ละผู้ใช้ เก็บบนเซิร์ฟเวอร์ เลิกหมุดของเราไม่กระทบคนอื่น ไม่เปลี่ยนผู้รับผิดชอบหรือความสำคัญของทั้งทีม และไม่เพิ่ม version งาน

## เชื่อมรายการรอปิดบิล

- สร้างรายการขายก่อนเมื่อใด ระบบสร้างงานติดตามหนึ่งงานต่อบิลใน transaction เดียว
- ผู้สร้างบิลรับผิดชอบเริ่มต้น กำหนดติดตามภายใน 24 ชั่วโมง ปรับผู้รับและกำหนดส่งได้
- ในการ์ด/รายละเอียดบิลมีปักหมุดและ “ส่งต่อ” หากมีสิทธิ์จัดการงานนั้น
- หัวหน้าเห็นงานในหน้าร้านและหลังบ้านตามสิทธิ์ ลิงก์จากงานเปิดบิลต้นทางพร้อมสาขาและเลขบิล
- ยังปิดงานเป็นเสร็จไม่ได้หากบิลยัง pending ป้องกันการซ่อนเงินค้างด้วยการกดจบงาน
- ปิดบิลสำเร็จ → งานเป็นเสร็จแล้ว; ยกเลิกบิลตามเงื่อนไข → งานยกเลิกอัตโนมัติ
- ระบบไม่ขยายสิทธิ์ดูข้อมูลการเงินเพียงเพราะถูกส่งลิงก์ ต้องมีสิทธิ์สาขาและคำสั่งของบิลตามเดิม

## การแจ้งเตือน

กระดิ่ง “การแจ้งเตือนงาน” มีทั้งหน้าร้านและหลังบ้าน แสดงจำนวนยังไม่อ่าน เปิดรายการเพื่อไปยังงาน และอ่านทั้งหมดได้ เก็บสถานะอ่านที่เซิร์ฟเวอร์ต่อผู้รับ

แจ้งเตือนงานใหม่ การส่งต่อ การเปลี่ยนสถานะ/อัปเดต และงานเกินกำหนด เตือนเกินกำหนดหนึ่งครั้งต่อ version เพื่อไม่เตือนซ้ำทุกครั้งที่รีเฟรช

การแจ้งเตือนเป็น **in-app polling ทุกประมาณ 20 วินาทีขณะเปิดเว็บ** ยังไม่ใช่ push เมื่อปิดเว็บ และไม่ส่งอีเมลหรือ Feishu โดยอัตโนมัติ

## หลักการปฏิทินขาย

- อ่านจาก orders/order_items กลาง ไม่ใช้ยอดจำลองในเครื่อง
- ใช้ `sale_occurred_at` เมื่อเป็นรายการขายก่อนที่มาปิดภายหลัง มิฉะนั้นใช้ `created_at`
- แสดงเวลา Asia/Bangkok แยกวันและชั่วโมงที่ฝั่งฐานข้อมูล
- ยอดรายวันเป็นยอดรวม VAT ของบิล completed/partially_refunded ไม่รวม voided/refunded
- ยังไม่หักยอดคืนบางส่วนในปฏิทินนี้ จึงไม่ควรเรียกว่า net settlement หรือใช้แทนรายงานกระทบยอดธนาคาร
- มูลค่า SKU เป็น line_total ก่อนส่วนลดท้ายบิล อาจไม่เท่าผลรวมยอดบิลหลังส่วนลด
- จำนวนบิล pending และเงินที่รับแต่รอลงบิลแสดงแยก ไม่บวกซ้ำกับบิลปิด
- อ่านยอดใหม่ทุก 1 นาทีขณะที่เปิดมุมมองนี้ ถ้ากำลังอ่านหรืออ่านล้มเหลวไม่แสดงศูนย์เป็นผลยืนยัน
- ผู้ใช้ scope own ดูเฉพาะยอดที่เป็น cashier/salesperson ของตน ขอบเขตสาขาถูกตรวจที่ server และ RPC

## สิทธิ์และการทดสอบ

ตาราง work, pins, activity และ notifications เป็น private/service-only ทุกคำสั่งผ่าน session, active employee, branch scope และ optimistic version ไม่เปิด RPC เขียนให้ anon/authenticated โดยตรง

ทดสอบครบชุด readiness และ migrations ทั้ง 47 ไฟล์: assignment/handoff, เหตุผลส่งต่อ, scope ข้ามสาขา, การเข้าด้วย task ID ตรง, pins ส่วนตัว, notification recipient, reminder dedupe, stale version, บิลสร้าง/ปิดงานอัตโนมัติ, วันขายจริง, Bangkok midnight/leap month และการอ่านแบบแบ่งหน้า

UI ทดสอบด้วยงานที่ติดป้าย UAT และบัญชีผู้พัฒนาปัจจุบัน ไม่มอบหมายงานทดสอบให้พนักงานคนอื่นและไม่สร้างยอดขายหรือรับเงินจริง ภาพหน้าจออาจแสดงตัวอย่างงาน UAT ก่อนปิดงานทดสอบ

## ขอบเขตที่ยังไม่รวม

- ไม่เปลี่ยนโมดูล CRM เดิมให้เป็น work center โดยอัตโนมัติ
- ยังไม่มีการแนบไฟล์/แชทกลุ่ม/งานวนซ้ำหรือซิงก์ปฏิทิน Google/Feishu
- การแจ้งเตือนไม่ทำงานเป็น OS push เมื่อปิดเว็บ
- ไม่อ้างว่ายอดในปฏิทินเป็นรายงานบัญชีสุทธิหลังคืนเงิน/settlement
