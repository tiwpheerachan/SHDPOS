# ขายก่อน รอข้อมูลเพื่อปิดบิล

เพิ่มวันที่ 22 พฤศจิกายน 2026 — migrations 0044-0045

## ใช้ในกรณีใด

สินค้าถูกขายจริงหรือจำเป็นต้องเก็บเงินไว้แล้ว แต่ยังไม่มี SN ครบ ยังไม่ยืนยันนโยบาย SN สินค้ายังปิดใช้งาน ราคา/หมวดหมู่ยังไม่เรียบร้อย หรือสต๊อกสาขายังไม่ถูกบันทึก

โหมดนี้บันทึกข้อเท็จจริงและเงินรับไว้บนเซิร์ฟเวอร์ ยังไม่สร้าง order ที่ completed จนกว่าจะผ่านการตรวจและปิดบิล ไม่สร้าง SN สมมุติหรือเปิดขายสินค้าให้ทุกคนโดยอัตโนมัติ

## วิธีทำจากหน้าขาย

1. เลือกสาขาที่ขายจริง
2. ติ๊ก “ขายก่อน · รอเติม SN / ข้อมูล แล้วปิดบิลภายหลัง”
3. ระบบแสดงสินค้าที่ยังไม่เปิดขายด้วย ป้ายระบุว่าใช้ได้เฉพาะขายก่อน
4. เลือก SKU และจำนวนลงตะกร้า สินค้าซ้ำรวมเป็นจำนวนตามปกติ
5. กด “ขายก่อน / บันทึกรอปิดบิล” จะเข้าได้แม้ SN ยังไม่ครบ
6. ระบุวันเวลาขายจริง ราคาขายจริงต่อชิ้น และเหตุผลที่ข้อมูลยังไม่ครบ ห้ามใช้ราคา 0 เพื่อเลี่ยงการตรวจ
7. ระบุให้ตรงว่าส่งมอบแล้วหรือยังไม่ส่ง
8. กด “บันทึกไว้ก่อน” หรือ “บันทึกและรับชำระ”
9. กรณีรับชำระ ตรวจผล EDC/บัญชีจริง ระบุเลขอ้างอิง แล้วบันทึก รองรับหลายวิธีรวมยอดกัน ไม่มีเงินสด
10. ทุกครั้งที่บันทึกรับเงิน เซิร์ฟเวอร์เก็บหลักฐานทันที แม้ปิดหน้าต่างภายหลังก็กลับมาทำต่อได้จากรายการเดิม
11. ดูต่อที่ “พักบิล → ขายก่อน · รอปิดบิล”

โหมดขายก่อนยังไม่รองรับแต้ม คูปอง หรือของแถม ระบบปฏิเสธแทนการตัดสิทธิ์ทิ้งเงียบ ๆ หากมีสิทธิ์เหล่านี้ต้องตรวจเงื่อนไขกับผู้ดูแลก่อนทำรายการ

## เติมข้อมูลและปิดบิล

1. เปิดแท็บ “ขายก่อน · รอปิดบิล” ภายใต้พักบิล รายการส่วนนี้อ่านจากเซิร์ฟเวอร์ ไม่ใช่ตะกร้าใน IndexedDB
2. ดูจำนวนรอปิดบิล เงินที่รับแล้วแต่ยังไม่ลงบิล และรายการค้างเกิน 24 ชั่วโมง
3. ค้นด้วย SKU ลูกค้า เหตุผล หรือเลข PEND
4. เปิดรายละเอียด จะเห็นวันขายจริง วันบันทึกเข้าระบบ เหตุผล ยอดที่ตกลง และเงินที่รับไว้
5. เติม SN หนึ่งเลขต่อบรรทัด ใช้เลขชิ้นที่ส่งให้ลูกค้าจริง สามารถกด “บันทึก SN / ข้อมูลส่งมอบไว้ก่อน” เพื่อเก็บบางส่วนและทำต่อจากอีกเครื่องในสาขา
6. แก้ master data ที่หน้าสินค้าให้พร้อม และตรวจยอดสต๊อก/ประวัติรับเข้าให้ถูกต้องก่อนปิดบิล
7. หากยังรับเงินไม่ครบ กดบันทึกรับชำระส่วนที่เหลือ เลขอ้างอิงเดิมไม่บันทึกซ้ำ
8. ยืนยันว่าส่งมอบสินค้าแล้ว แล้วกด “ตรวจข้อมูลและปิดบิลจากเงินเดิม”
9. ระบบตรวจสินค้า active ราคา สิทธิ์ส่วนลด SN ทุกชิ้น ความเป็นเจ้าของ SN และ Available stock
10. ราคาขายจริงต่างจากราคากลางต้องให้ผู้มีสิทธิ์ `pos.price_override` ปิดบิล ราคาที่ตกลงและเงินรับไม่ถูกแก้ให้เท่าราคากลางย้อนหลัง
11. เมื่อสำเร็จ บิล เงินรับเดิม การปล่อยยอดที่กัน และการตัดสินค้าเกิดใน transaction เดียว บันทึกเลขอ้างอิงกลับไปที่รายการเดิม
12. หากข้อมูลไม่ผ่าน ยอดกันสินค้า เงินรับ และ SN ที่เก็บไว้ยังอยู่ครบ ให้แก้ข้อมูลและลองใหม่ ไม่ต้องรับเงินอีกรอบ

## สถานะ

| สถานะหลัก | ความหมาย |
| --- | --- |
| pending | รอเติมข้อมูล อาจยังไม่รับเงิน รับบางส่วน หรือรับครบแล้ว ตรวจยอดเงินประกอบ |
| posted | ปิดเป็นบิลขายกลางสำเร็จแล้ว ดูย้อนหลังได้ |
| cancelled | ยกเลิกก่อนรับเงินและก่อนส่งมอบ พร้อมคืนยอดที่กัน |

ไม่ลบรายการที่มีเงินรับแล้ว ต้องผ่านกระบวนการคืนเงิน ส่วนรายการส่งมอบแล้วต้องผ่านการรับคืน ไม่เปลี่ยนสถานะให้เหมือนไม่เคยส่งของ การเชื่อม refund ของ pending sale ยังไม่เพิ่มในรอบนี้

## หลักการด้านสต๊อกและ SN

- If no stock row exists, create On Hand = 0 with opening_pending = true and reserve the pending quantity immediately. This does not create physical stock. After actual opening inventory is recorded, the reservation remains until posting or eligible cancellation.
- ยอดที่กันทำให้ Available ลดลง ส่วน On Hand ยังไม่ตัดจนปิดบิล จึงต้องอ่านคู่กับรายการส่งมอบแล้วรอตัดยอด และไม่ใช้ On Hand เดี่ยว ๆ เป็นผลตรวจนับจริงระหว่างมีรายการค้าง
- ถ้ายอดไม่พอ อนุญาตให้เก็บข้อเท็จจริงเป็นรายการค้างพร้อม flag `stock_short` โดย Available อาจติดลบ การปิดบิลยังต้องกระทบยอดจริงให้ผ่าน
- If no stock row exists, create On Hand = 0 with opening_pending = true and reserve the pending quantity immediately. This does not create physical stock. After actual opening inventory is recorded, the reservation remains until posting or eligible cancellation.
- SN ที่ทราบแล้วถูกกันใน `pos_deferred_serial_claims` ไม่ให้บิลปกติหรือรายการขายก่อนอีกใบใช้ซ้ำ
- SN ที่ยังไม่มีเว้นว่างได้ใน pending แต่ต้องครบและอยู่ในสาขา/สินค้า/สถานะที่ถูกต้องก่อนปิดบิล
- การแก้ SN มี version และ audit; การชนกันจากหลายเครื่องให้โหลดรายการล่าสุดก่อนแก้ต่อ
- สินค้าชุดบันทึกเป็น pending ได้ แต่ยังปิดบิลไม่ได้จนกว่าจะมี flow BOM ที่รองรับ

## วันที่และรายงาน

เก็บวันขายจริงใน `pos_deferred_sales.occurred_at` และเมื่อปิดบิลคัดลอกเป็น `orders.sale_occurred_at` พร้อม `deferred_sale_id`; วันสร้างบิลในระบบ `created_at` ยังเป็นเวลาที่ปิดบิลจริง ไม่เปลี่ยนหมายเลขเอกสารหรือแอบแก้วันที่สร้างเอกสารเก่า

เงินรับใน pending แสดงแยกบนหน้าพักบิล ยังไม่ถูกรวมเป็นบิล completed ในรายงานยอดขายเดิม เมื่อปิดบิลจึงเข้าบิลขายครั้งเดียว งานปรับรายงานการเงินทั้งระบบให้แสดงเงิน pending แยกทุกหน้าเป็นงานต่อยอด ไม่ควรถือว่ารายงาน completed ครอบคลุมเงินรับ pending แล้ว

เหตุการณ์ `sale.committed` สำหรับ OW เกิดตอนปิดบิลเท่านั้น มีวันขายจริงและ deferred_sale_id กำกับ แต่ยังรอ contract เขียนกลับ OW เช่นเดียวกับ Checkout ปกติ

## การตรวจสอบที่ทำ

- ทดสอบ migration ทั้ง 45 ไฟล์ใน PostgreSQL แยก พร้อมใช้ production order writer จริง
- missing SN/master data, ราคาจริงมากกว่าศูนย์, ยอดไม่ตรง, SN ซ้ำ, จำนวนไม่ถูกต้อง และ guard แต้ม/คูปอง/ของแถม
- สร้างซ้ำไม่กันยอดซ้ำ บันทึกรับเงินซ้ำไม่เพิ่มเงิน ยอดเกินถูกปฏิเสธ
- บิลอื่นใช้ SN ที่กันไว้ไม่ได้ บันทึก SN บางส่วนและ version conflict
- ปิดบิลล้มเหลวแล้ว reservation/SN claims/เงินยังอยู่ครบ
- ปิดบิลซ้ำไม่ตัดยอดซ้ำ ไม่สร้าง payment หรือ OW event ซ้ำ เก็บวันขายจริงและต้นทุนตามบิล
- If no stock row exists, create On Hand = 0 with opening_pending = true and reserve the pending quantity immediately. This does not create physical stock. After actual opening inventory is recorded, the reservation remains until posting or eligible cancellation.
- RPC ทุกตัวเป็น service-only API ตรวจ session สิทธิ์ และสาขา
- ทดสอบ UI จริงบน localhost: สร้างรายการ UAT ที่ไม่รับเงิน/ไม่ส่งมอบ เปิดจากพักบิล บันทึกข้อมูล และยกเลิก พร้อมเก็บประวัติ ไม่มีการสร้างยอดขายหรือรับเงินทดสอบจริง

SN policy review: pending-sale reservations alone may be excluded from the physical-inventory guard when selecting an initial SN policy. Existing On Hand, real serial records, and other reservations still require reconciliation.
