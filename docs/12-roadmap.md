| 2. Orders & Receipt | 🟢 ใช้งานได้จริง | รายการบิล พิมพ์ซ้ำ ยกเลิก สลิป ESC/POS ภาษาไทย |

| 7. Customer / Member | 🟡 DB ครบ, UI พื้นฐาน | ยังไม่มีหน้าจัดการสมาชิก/แต้ม |
| 8. Admin / Permission | 🟢 ใช้งานได้จริง | matrix + scope + approval ครบ |

## เฟสถัดไป

### เฟส 2 — ปิดช่องว่างของ v1 (2–3 สัปดาห์)
- UI เติม/ถอนเงินสดระหว่างกะ + รายงานกระทบยอดเงินสด
- สแกน serial ทีละชิ้นตอนรับของโอน + discrepancy workflow เต็มรูปแบบ
- หน้าจัดการลูกค้า/สมาชิก + แต้ม + store credit ใช้จ่ายได้จริง
- ใบเสนอราคา: พิมพ์/ส่งอีเมล + ตั้งวันหมดอายุอัตโนมัติ
- หน้าจัดการ `sync_conflicts` สำหรับผู้จัดการ

### เฟส 3 — ระบบภาษีและการเงิน (3–4 สัปดาห์)
- e-Tax Invoice & e-Receipt เต็มรูปแบบ (Edge Function + ผู้ให้บริการ CA)
- ใบลดหนี้อัตโนมัติเมื่อคืนสินค้า
- รายงานภาษีขายรายเดือนสำหรับ ภ.พ.30
- กระทบยอดบัตรเครดิต/QR กับ statement ธนาคาร
  (ข้อมูลเดิมมีคอลัมน์ `เวลาเก็บเงินของธนาคาร` และ `ยอดเงินค้างชำระ` อยู่แล้ว)

### เฟส 4 — เชื่อมระบบเดิม (3–4 สัปดาห์)
- Adapter กับ **JST (聚水潭)**: ดึง product master + สต๊อก, ส่งยอดขายกลับ
- ส่งข้อมูลเข้า **BigQuery** ให้ต่อกับ ecom-data-platform
  (รวมยอด offline + Shopee + TikTok ในที่เดียว)
- รับออเดอร์ "รับสินค้าหน้าร้าน" จาก Shopee/Lazada เข้ามาที่ POS โดยตรง
  (ข้อมูลเดิมมี 2,292 บรรทัด ปัจจุบันคีย์มือ)

### เฟส 5 — ยกระดับ (ต่อเนื่อง)
- **Alert rules อัตโนมัติ** ตาม `11-audit-log.md` (เงินสดขาด, ยกเลิกบิลบ่อย, พิมพ์ซ้ำผิดปกติ)
- คอมมิชชัน/KPI พนักงานคำนวณอัตโนมัติ (ต่อยอดจาก MC KPI ที่ทำอยู่แล้ว)
- ตู้ vending — รับยอดขายผ่าน API ของผู้ให้บริการตู้
- แอปติดตั้งด้วย Tauri สำหรับเครื่องหน้าร้าน
- โปรโมชัน: ซื้อ X แถม Y, บันเดิล, คูปอง, ราคาตามช่วงเวลา
- ระบบเคลม/ซ่อมเต็มรูปแบบ (ผูกกับ serial + ประกัน)

## ความเสี่ยงที่ต้องจับตา

| ความเสี่ยง | ผลกระทบ | การรับมือ |
|---|---|---|
| สต๊อกตั้งต้นไม่ตรง | สต๊อกติดลบทันทีหลังเปิดใช้ | นับจริงก่อนเปิดทุกสาขา + เปิดเป็นสาขา ๆ ไป |
| พนักงานไม่คุ้นระบบใหม่ | ขายช้า ลูกค้ารอนาน | อบรม + ขายคู่ขนานระบบเดิม 1–2 สัปดาห์ |
| เครื่องพิมพ์คนละรุ่นกันทุกสาขา | สลิปเพี้ยน/ภาษาไทยไม่ออก | ทดสอบทีละรุ่น เก็บ profile ไว้ใน `terminals.printer_profile` |
| เน็ตบางสาขาไม่เสถียร | งานค้างซิงก์สะสม | offline-first รับได้อยู่แล้ว + เฝ้าดูจำนวนงานค้าง |
| ข้อมูลสินค้า/ราคาไม่นิ่ง | ขายผิดราคา | ให้ JST เป็น source of truth แล้ว sync ทางเดียว |
